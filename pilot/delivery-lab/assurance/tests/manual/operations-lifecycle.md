## Packaging (A/M with producer inputs)

**PKG-01 — clean build.** Given published app SHA, fully hashed dependency lock, immutable base index and linux/amd64 manifest/config, accepted suite SHA and exact build tools, independently retrieve and verify all inputs. Rebuild in clean permitted environment using the published instructions and no mutable branch substitutions. Expect compatible complete pinned dependencies, documented entrypoint/port/config/volume, non-root execution and same source/contract identity. Record actual output manifest/config digest and archive SHA-256 for each build; do not require identical output digest unless reproducibility policy explicitly specifies it. Explain differences; no clean-build claim from producer logs alone. Missing pins/lock/route/CI is UNAVAILABLE, not a local-build waiver.

**PKG-02 — package and confinement.** Inspect image metadata, package inventory/layers and rendered configuration, then independently inspect the running pilot. Expect non-root UID/GID; only declared data path persistently writable, read-only root and small /tmp tmpfs, no privileged/host network/PID or Docker socket/credentials/arbitrary mounts, dropped capabilities/no-new-privileges, bounded resources/logs and session-independent restart policy. Baseline proposed numeric values are selections to record, not invented runtime facts. Examine application logs for the declared metadata-only policy and no request bodies/names/secrets. Safe bad fixture with root user, socket mount, identity override or real data must fail qualification (HAR-08/09); do not launch it. No host-wide inspection or unrelated data collection.

**PKG-03 — artifact/CI provenance.** From authorized publication destination independently download OCI manifest/archive, checksum, lock/inventory and labelled producer/independent logs. Verify archive SHA-256, manifest bytes' digest, image config/platform and source-to-image record; import/use only through authorized pilot route. Config/image ID is not manifest digest. Bind exact workflow commit/run/artifact IDs and retention location. Check reviewed full action SHAs and actual authorized administrator publication. Corrupt archive/mismatched source fixture aborts before use. Current CI availability is UNKNOWN; no modifications to .github or credential expansion are authorized here. Native CI decision/alternate route, if needed, belongs to CEO/Bogdan and must be recorded.

**LIFE-01 — published identities.** Require remotely retrievable C0 and C1 exact SHAs/paths/manifests, accepted TS and TC references, independent suite/harness report identities and affected criteria. A branch name, mutable tag or report from another build does not bind the result. Keep producer and independent reports separate. No application implementation inspected for TS expectations.

**LIFE-03 — fresh continuation.** Before producer handoff/end, exact candidate, reports/revisions/findings/limits and next action are saved/read back. **LIFE-04 — correction and fresh evidence.** Engineer's C1 change preserves scenario oracle; publish changed paths and impact analysis, then re-examine affected API/UI/Unicode/data/recovery paths plus required full regression and independent manual obligations. Reuse existing assignments; unresolved dependencies stay native, no source-done examination cycle.

**LIFE-05 — final native decisions.** Technical reports and limitations saved/read back; only current native participant can approve/request changes with reason. Human's actual C1 business/appearance/usability verdict and configured native final approval are required. A completed examination or automated green run is not source acceptance.
