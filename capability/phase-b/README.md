# Static capability protocol

No capability result is claimed by this prepared package. Use actual, scoped agent identities after runtime/access readiness. Actions stays disabled; no executable test program or application is introduced.

The Product Engineer owns the fixture on its authorized branch. Fixed required manifest fields are fixtureId, candidateVersion, purpose, acceptanceCriterionIds (a nonempty array of strings), expectedOutcome and publicSafe=true. C0 deliberately omits acceptanceCriterionIds; C1 restores it and changes candidateVersion from C0 to C1. All values are synthetic and public-safe.

1. Record baseline governance, distinct identities, branch rules, disabled Actions, absence of deployment effects and successful remote access/confinement.
2. Engineer publishes C0 and saves/reads back full remote SHA, paths, relevant document revisions and retrieval evidence before release of separate R0 and V0. They identify the missing required field and finish with FAIL after saving/reading back their reports and continuation. The producer then saves/reads back C0, exact report revisions, findings, limits and continuation, and submits unchanged C0 for native review as the final required action of that run.
3. Incoming Assurance verifies and records actual stage/currentParticipant, immutable C0 and original-producer returnAssignee in its own continuing context. It saves/reads back findings and continuation before requesting changes natively, with rationale in the same decision operation. The transition is its final required action. The incoming original Engineer verifies and records the actual native decision/outcome and return; no receipt from the outgoing run is required. Conduct a negative participant assertion only under its own explicit authorization and the separate execution contract below.
4. Before the producer run ends for an authorized scoped reset, save/read back its continuation packet with C0 and findings. Verify the run has ended and operator metadata proves the exact task scope before the supported task-scoped reset. Record actual fresh-session recovery of C0, findings and remaining actions without the prior transcript. A previous native transition is not evidence that this later producer run ended or that reset is authorized.
5. Original Engineer corrects/publishes C1. Separate R1/V1 retrieve C1 independently and record fresh results before native resubmission and acceptance.
6. In a separate mock readiness source, genuinely wait through a saved human-only interaction for a dummy fact before attaching the review policy. Record producer-phase attachment/read-back, candidate publication and separate R/V evidence before submission. The incoming participant records its own verification and decision evidence according to step 3. Do not claim real hosting readiness.
7. Independent framework review and final capability verification examine the frozen framework candidate and completed fixture/transition records. Save/read back their reports and continuation before completion. The source then enters native non-author review after its own evidence/read-back; human review of Phase B findings does not authorize Phase C. A framework process correction cannot supply missing live participant proof or by itself accept Phase B.

## Isolated participant-check execution

Keep the test target's ownership lifecycle separate from the test actor's execution assignment. The actor uses its own ordinary identity/run and does not take the target's checkout or change policy/assignee to gain access. Before any separately authorized attempt, establish supported access/route preconditions without a decision dispatch, stable native review/currentParticipant/original returnAssignee, and a real native wait/continuation arrangement for the reviewer. Account for reviewer checkout and concurrent metadata repair; ordinary API writes can change native state. A comment promising abstention is not a lock or scheduled continuation.

Persist/read back authorized scope, exact non-secret request, actor/run, target and execution identities, immediate before-state and evidence destination before dispatch. Record response and after-state, then save/read back the complete findings/receipt and continuation on the execution assignment before its own final handoff/completion. Require participant-specific wrong-actor rejection and unchanged state for PASS. Unrelated access/route/transport errors or concurrent changes are inconclusive; unauthorized success is FAIL and stops the check without cleanup. Do not silently substitute an unrelated rejection.

Reconcile interrupted consequential operations from durable evidence and live native state before another mutation. `prepared`, `dispatch-started`, `response-confirmed` and `evidence-saved` are evidence labels, not task statuses or exactly-once guarantees. Missing evidence is UNKNOWN, not proof of non-execution or permission to repeat. A stopped run, new marker or revised plan grants no new attempt allowance. Use native idempotency/recovery only for supported operations within current authorization. Preserve prior revisions and consumed/unknown attempts.

CEO coordinates recovery on the existing coordinator with a concrete supported next action and permitted owner, or an exact remaining human decision. Keep unresolved acceptance dependencies while using separately authorized production work when required; no reciprocal source/target-completion dependencies or loops on completed blockers. Stage assignments in backlog with their owners and exact inputs before release; backlog alone does not authorize examination or a probe. Reuse existing examination assignments for fresh affected evidence. Accepted pilot sources are not reopened by a framework correction.

Do not substitute configuration documentation for observed results. Stop dependent work on missing confinement, wrong participant/return, unknown reset scope, missing immutable identities or unexpected external effects. Keep sensitive runtime and decision evidence in Paperclip. No custom budget, duration or run-count limits are imposed.
