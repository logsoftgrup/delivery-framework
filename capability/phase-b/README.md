# Static capability protocol

No capability result is claimed by this prepared package. Use actual, scoped agent identities after runtime/access readiness. Actions stays disabled; no executable test program or application is introduced.

The Product Engineer owns the fixture on its authorized branch. Fixed required manifest fields are fixtureId, candidateVersion, purpose, acceptanceCriterionIds (a nonempty array of strings), expectedOutcome and publicSafe=true. C0 deliberately omits acceptanceCriterionIds; C1 restores it and changes candidateVersion from C0 to C1. All values are synthetic and public-safe.

1. Record baseline governance, distinct identities, branch rules, disabled Actions, absence of deployment effects and successful remote access/confinement.
2. Engineer publishes C0. Separate R0 and V0 bind to its full remote SHA and identify the missing required field. Both examinations finish with FAIL; the producer then submits unchanged C0 for native review.
3. Capture active participant and original-producer returnAssignee. Assurance requests changes natively. Conduct only the specifically authorized negative participant assertion on the isolated task and record rejection with unchanged state; any unauthorized success stops the check.
4. Save the continuation packet, end the producer run, verify operator metadata and perform the supported task-scoped reset. Record actual fresh-session recovery of C0, findings and remaining actions without the prior transcript.
5. Original Engineer corrects/publishes C1. Separate R1/V1 retrieve C1 independently and record fresh results before native resubmission and acceptance.
6. In a separate mock readiness source, genuinely wait for a human-only dummy fact before attaching the review policy. Record producer-phase attachment/read-back, candidate publication and separate R/V evidence, then the native decision. Do not claim real hosting readiness.
7. Independent framework review and final capability verification examine the frozen framework candidate and completed fixture/transition records. The source then enters native non-author review; human review of Phase B findings does not authorize Phase C.

Do not substitute configuration documentation for observed results. Stop dependent work on missing confinement, wrong participant/return, unknown reset scope, missing immutable identities or unexpected external effects. Keep sensitive runtime and decision evidence in Paperclip. No custom budget, duration or run-count limits are imposed.
