# Independent verification assignment

- Outcome and verifier independent of the candidate producer:
- Exact application/artifact SHA and paths:
- Accepted scenario revision, suite SHA and immutable image digest, or explicit static/manual not-applicable reasons:
- Environment/configuration identity and permitted access:
- Criterion-by-criterion expected outcomes and procedure:
- Clean retrieval/execution context and run identity:
- Required evidence/report locations and privacy classification:
- Applicable document revisions, native participant/original return identity and verification record:
- Continuation destination and permitted next owner/action:

Retrieve the recorded candidate independently; never use an unspecified branch head or producer's dirty checkout. Record expected/actual and PASS/FAIL/UNAVAILABLE for each criterion. Keep the candidate unchanged. Report the original defect and regressions on correction rounds; old evidence is not a pass for a new SHA.

Stage in backlog under the intended verifier. Release only with authorized scope, criteria, full remote SHA, paths and relevant document revisions; no source-completion prerequisite. At wake, verify actual task/native state, original return identity and pinned inputs in the verifier's own continuing context.

Save/read back findings, report revisions, exact evidence, limitations and [continuation](../continuation.md) before finishing the evidence task done, including FAIL. Completion is the final required action, with no required outgoing-run receipt afterward. Missing candidates, suite or environment require an actual unresolved dependency, pending interaction/approval or concrete blocker action with a permitted owner. Do not loop on completed blockers. The source's active native participant separately handles acceptance/return, with rationale in the same decision operation. Do not infer business acceptance from automated results.

An explicitly authorized platform test uses an actor execution assignment separate from its target's native ownership lifecycle. Validate access/route and stable review/concurrency preconditions without a decision attempt. Persist actor/run, exact non-secret request/response and before/after state before the execution assignment transitions. Require participant-specific rejection and unchanged state for a wrong-actor criterion; unrelated errors/concurrent changes are inconclusive. Reconcile interruptions against live state; missing evidence is UNKNOWN and grants no redispatch allowance.
