# Fresh-session continuation packet

Persist and read back a concise packet on the execution task before ending a session or making an ownership-changing/terminal native transition. Save all indispensable artifacts and report revisions first. The transition is the final required action of that run; no mandatory outgoing-run command, comment or receipt follows it. A normal packet is 200–400 words; this is a writing guideline, not a run/token limit.

```text
Task / source task / current native stage and participant:
Current actor/run and verified original producer / native returnAssignee:
Outcome and remaining criterion IDs:
Repository, authorized branch, remotely retrievable full SHA, exact paths, PR and image digest:
Scenario revision, suite SHA and CI/execution run (or explicit static/manual N/A):
Completed work, report revisions and evidence references:
Decisions/reasons, known failures, pending interactions and real blockers:
Interrupted operation: exact non-secret request, durable response, before/after state and uncertainty:
Next concrete actions and original producer / returnAssignee:
Native continuation mechanism, permitted next owner and release prerequisites:
Unpublished workspace changes and access/environment constraints:
```

A fresh session checks current task authority, actual native stage/currentParticipant/returnAssignee, this packet and exact referenced artifacts. The incoming participant records verification of immutable candidate and original return identity in its own continuing context, including any native decision/outcome observed after the prior transition. It resumes only authorized scope and decides only when active. The packet is evidence, not permission. It must not require the old transcript or private memory. Preserve uncommitted work; never call it a ready candidate.

## Interrupted consequential operations

Reconcile durable request/result records with live native state before another mutation. Track `prepared`, `dispatch-started`, `response-confirmed` and `evidence-saved` as evidence labels, not task statuses or an exactly-once guarantee. A prepared request or dispatch marker alone proves neither execution nor non-execution. Missing response evidence means UNKNOWN; never infer permission to repeat. Preserve the original history, exact request, actor/run, observed response/state, timestamps, report revisions and limits. Use native recovery/idempotency only where that exact operation supports it and current authority permits retry.

For a separately authorized platform test, keep the target lifecycle separate from the actor execution assignment. Record access/route readiness without consuming a decision attempt, stable before/after snapshots and reviewer concurrency. Save/read back the result and continuation on the execution assignment before its own transition. A target transfer must not cancel the only recorder. Unrelated errors/concurrent changes are inconclusive; a new plan or stopped run does not renew an attempt allowance.

The CEO inspects native recovery notices and coordinates on the existing coordinator using ordinary comments. Record a concrete disposition and supported native next action, or name the exact remaining human decision. Use actual unresolved dependencies, a pending interaction/approval or a blocker action with a permitted owner to represent the wait. Completed dependencies and prose promises cannot schedule continuation. Preserve unresolved acceptance gates while making separately authorized correction production executable; do not add reciprocal completion dependencies.

Use only the supported scoped reset after an authorized operator verifies the exact non-null task key and the producer run has ended. Record before/after session/run identities. No global reset, hidden session-file deletion or database manipulation. If scope cannot be proven, report UNAVAILABLE and stop the dependent recovery check.
