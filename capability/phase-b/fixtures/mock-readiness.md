# Static mock readiness record

This synthetic fixture illustrates a coordination and native review-policy
transition. It does not establish real environment readiness or authorize
provisioning, deployment, framework acceptance, or cross-company operations.

The adjacent `mock-readiness.json` contains a fictional example. Its example
fact is not the human's answer. Actual interaction and resolver identities,
answers, run timestamps, policy snapshots, decisions, and evidence reports
remain in private task records. Publishing this fixture does not prove that
any step in its expected sequence happened.

An evidence package binds this candidate's exact published commit and paths to
those private records. Review and verification are distinct assignments and
examine the same immutable candidate. Each report records criterion, author,
task and role, expected and actual results, PASS/FAIL/UNAVAILABLE, timestamps,
input revisions, run and decision identities where available, and limitations.
Completed examination can have an adverse verdict. The producer waits on both
reports before submitting the native review decision.

Before submission, the private policy read-back must show the designated
independent reviewer and producer ownership. The active participant and native
return-assignee behavior can be observed only when the native gate runs. They
must not be reported as already proven by a configured policy or this fixture.

No executable product, automated test suite, workflow, service, environment,
image, or deployment is included. Suite SHA and image digest are not applicable
to this manual static fixture. Separate review and verification performed by
the same assurance agent retain a correlated-omission limitation.
