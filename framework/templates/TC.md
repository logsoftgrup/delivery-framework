TC may proceed before or alongside application implementation using fixtures/stubs. Publish the exact suite SHA. Demonstrate discrimination on controlled good/bad inputs without weakening expectations. Record skips and coverage gaps explicitly. Harness verification proves the test tool, not application acceptance. Assurance cannot accept its own suite. Phase B manual static verification does not instantiate TC.

Prepare in backlog with the intended author; release with authorized scope, criteria and reachable immutable inputs. Save/read back the published suite SHA, paths, scenario revisions and retrieval evidence before releasing separate review/harness verification. These examinations never depend on TC completion and can finish with FAIL. Once they finish, save/read back their report revisions, findings, limitations and [continuation](../continuation.md), then submit to native review as the final required action. Incoming participants verify actual stage/currentParticipant, exact suite and original returnAssignee in their own context. Include decision rationale in the native operation; no mandatory outgoing-run action follows it. Changes return to the original author and require fresh affected evidence. Match waits to their native cause; reconcile interruptions before retry and retain UNKNOWN where evidence is missing.
